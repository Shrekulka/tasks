# Требования и решения: Telegram-бот лесных порад (RAG по документам)

Версия 2.2 · 23.10.2026 · основано на тестовом задании Broscorp, диалоге с заказчицей и проверке работающего экземпляра
(Мишка-шкряботушка). Документ описывает то, что реализовано. Переменные окружения:
`docs/configuration.md`. Правила для кодинг-агента: `AGENTS.md`.

## 1. Исходное задание и как оно понято

| Пункт задания | Как понят | Чем закрыт |

## 2. Что делает продукт

Звери пишут боту вопросы текстом в личные сообщения. Бот отвечает **только по документам** общей
базы, по-украински, и всегда называет источник. Звери сами пополняют базу, присылая PDF, DOCX
или TXT. Стандартные документы («Лісовий архів») бот знает со старта.

## 5. Решения исполнителя

| № | Решение | Обоснование |
|---|---|---|
| D1 | Документы архива не публикуются. В репозитории `samples/archive/` с вымышленными документами. При каждом старте папка синхронизируется с базой по SHA-256: новые файлы добавляются, изменённые переиндексируются, удалённые убираются, переименованные получают новый путь без переиндексации | R12, запуск одной командой работает у любого проверяющего |
| D2 | Документы зверей и архива различаются по `source_type`; синхронизация архива документы зверей не удаляет | R5 |
| D3 | Ответ: 2–5 предложений по сути, источники отдельным блоком | Удобно читать в мессенджере |
| D4 | Лимит файла 20 МБ (`MAX_FILE_MB`) | Предел скачивания файла ботом в Telegram |
| D5 | Дубль определяется по SHA-256 среди всей коллекции. Бот называет, кто и когда документ добавил (для архива «Лісовий архів») | Не засорять базу, сохранить авторство |
| D6 | При противоречии бот описывает обе позиции с обоими источниками. Поиск берёт лучший фрагмент каждого документа раньше, чем добирает остальные | Выбор остаётся за зверями. Гарантии «найдём любое противоречие» нет |
| D7 | `/mydocs`: свои документы постранично, удаление с подтверждением, проверка владельца в SQL по `from_user.id` | В общей базе нужен способ исправить ошибку |
| D8 | Если ни один фрагмент не ближе порога релевантности, бот отвечает фиксированной фразой без обращения к LLM. Порог настроен «полнота прежде всего»: часть вопросов без ответа проходит его и отсекается моделью (`found=false`). Дополнительно `RELEVANCE_MARGIN` убирает шлейф слабо связанных фрагментов | R9, экономия квоты. На реальных данных расстояния ответных и безответных вопросов перекрываются |
| D9 | Не-текстовые сообщения: вежливое объяснение | Предсказуемое поведение |
| D10 | PDF без текстового слоя и пустые файлы отклоняются с объяснением. OCR вне объёма | Честный отказ лучше пустого индекса |
| D11 | Время хранится в UTC, показывается по `DISPLAY_TIMEZONE` (Europe/Kyiv) | Звери в одном регионе |
| D12 | При загрузке бот говорит, что документ увидят все звери | Прозрачность общей базы |
| D13 | Название документа: имя файла без расширения; страница (PDF) или заголовок раздела (DOCX), если известны | Единообразие |
| D14 | Каждый вопрос обрабатывается независимо, без истории диалога | Простота |
| D15 | В группах бот отвечает подсказкой только на команды | R1 |
| D16 | PostgreSQL + pgvector, SQLAlchemy 2.0 async. Колонка `vector` без размерности, модель и размерность фиксируются в таблице `app_meta` | Один источник правды, смена модели не смешивает векторы |
| D17 | Каркас по шаблону автора (aiogram 3), лишнее удалено | Чистый репозиторий |
| D18 | Репозиторий публичный, только код: без `.env`, документов архива, данных зверей, номера телефона | R12 |
| D19 | Inline-клавиатуры только в `/mydocs`; меню команд через `set_my_commands` | Кнопки там, где они экономят действия |
| D20 | Один язык интерфейса, все тексты в `lexicon/lexicon_uk.py` | R2 |
| D21 | Ролей и админки нет | Нет в требованиях |
| D22 | Ограничение частоты вопросов и загрузок на зверя (`ThrottlingMiddleware`), один активный вопрос на зверя | Защита общей базы и квоты LLM |
| D23 | Эмбеддинги считает локальная мультиязычная модель, скачивается при сборке образа; в работе `HF_HUB_OFFLINE=1` | Запуск без сети, лимиты провайдера не тратятся |
| D24 | Индексация идёт в фоне. Пока документ в статусе `processing`, в поиске он не участвует | Не блокировать бота |
| D25 | Таблицы создаются при старте (`create_all`) | Достаточно для задания |
| D26 | LLM: бесплатные модели OpenRouter. Список берётся из `GET /models` и проходит fail-closed фильтр: id оканчивается на `:free`, цены нулевые, текстовый вход и выход, достаточный контекст | Groq недоступен |
| D27 | Провайдер подключается через адаптер (`external_services/llm/registry.py`), политики ошибок и цен принадлежат адаптеру | Смена `LLM_BASE_URL` одна совместимости не гарантирует |
| D28 | Лимиты бесплатных моделей общие на аккаунт. Дневной остаток читается из `free_model_daily_requests` (`GET /key`), локальный счётчик запасной | Документация OpenRouter |
| D29 | Общий потолок запросов в минуту, кэш ответов, учёт остатка квоты | Суточный лимит быстро исчерпывается |
| D30 | Ошибки провайдера классифицируются по статусу, заголовкам и телу, а не по одному коду (`error_policy.py`) | 402 и 429 бывают разной природы |
| D31 | Закреплённые в `LLM_MODELS` модели принимаются, только если они прошли тот же фильтр. Используются только бесплатные варианты `:free`; платные модели и покупка кредитов для повышения квоты не используются | Исходное требование — бесплатный уровень |
| D32 | HTTP через `aiohttp`, свой сплиттер вместо внешней библиотеки | Меньше зависимостей |
| D33 | Архив приоритетнее зверей: если документ зверя совпал по SHA-256 с файлом архива, запись становится архивной, автор очищается, удалить её через `/mydocs` нельзя | Стандартный документ не должен пропасть из-за удаления копии |
| D34 | Запись `failed` переиспользуется только запросом того же типа источника; архив может забрать failed-запись зверя, зверь запись архива не может | Нельзя присвоить чужую запись |
| D35 | Кэш ответов привязан к версии коллекции: любое добавление, удаление и повышение документа его сбрасывает. Ключ включает версию промпта, модель эмбеддингов, `TOP_K`, порог | Не вернуть совет из удалённого документа |
| D36 | Пустая или отсутствующая папка архива не стирает архивные документы в базе | Пустая папка чаще означает ошибку монтирования |
| D37 | Название документа при дубликатах в архиве берётся из лексикографически первого пути | Детерминированный результат |

## 7. Функциональные требования

- **FR-1 `/start`, FR-2 `/help`.** Что умеет бот, форматы, лимит, предупреждение «документы видят все», `/mydocs`.
- **FR-3 Вопрос.** Только личный чат и текст. Длина до `MAX_QUESTION_CHARS`. Один активный вопрос на зверя. Вопрос превращается в вектор (префикс `query:`), ищутся ближайшие фрагменты документов в статусе `ready`, отсеиваются по порогу, выбираются разные документы. Нет фрагментов: фиксированная фраза без LLM. Иначе LLM получает пронумерованные фрагменты и возвращает JSON `found`, `answer`, `used`.
- **FR-4 Формат ответа.** Совет и блок источников, собранный кодом из реестра по номерам `used`. Для архива: название и «Лісовий архів». Для зверя: название, страница, имя, `@username`, дата и время. Текст экранируется под HTML и режется под лимит Telegram.
- **FR-5 Нет ответа.** Фраза «не знайшов поради», источников нет.
- **FR-6 Приём документа.** Расширение и размер проверяются до скачивания. После скачивания: сигнатура и содержимое, SHA-256, дубль, разбор (защита от архивной бомбы и тяжёлых PDF), запись со статусом `processing`, подтверждение. Фоновая индексация: фрагменты, эмбеддинги, запись, `ready`. Для больших документов сообщения «обробляю» и «готовий». Подпись к файлу не считается вопросом.
- **FR-7 `/mydocs`.** Список своих документов (`MYDOCS_PAGE_SIZE` на странице), «Видалити» с подтверждением, навигация. Владелец проверяется в запросе.
- **FR-8 Синхронизация архива.** При каждом старте. Идемпотентна, ошибка одного файла не останавливает остальные, скрытые файлы пропускаются.
- **FR-9 Устойчивость.** Ошибки LLM превращаются в понятные сообщения (дневной лимит, минутный лимит, сервис недоступен). Необработанное исключение логируется, зверь получает короткое сообщение. При остановке бот дожидается фоновых задач.
- **FR-10 Прочее.** Не-текстовые сообщения, группы, неизвестные команды.

## 8. Нюансы и граничные случаи

| Ситуация | Поведение |
|---|---|
| Документ с подписью-вопросом | Подпись не вопрос: бот подтверждает приём и просит задать вопрос отдельно |
| Несколько файлов в одном сообщении | Каждый файл отдельно, лимит загрузок считается по каждому |
| Двое одновременно шлют один файл | Уникальный индекс по `sha256`, второй получает ответ о дубле |
| У файла нет имени | `document_<id>` с расширением по MIME |
| Расширение не соответствует содержимому | Отказ с объяснением |
| TXT в cp1251 | Сначала UTF-8, затем cp1251 |
| DOCX с таблицами и колонтитулами | Таблицы построчно, колонтитулы игнорируются, порядок абзацев сохраняется |
| PDF с паролем или повреждённый | Отказ с объяснением, бот не падает |
| Вопрос во время индексации | В поиске участвуют только документы `ready` |
| Вопрос на русском | Ответ на украинском (проверка языка), мультиязычные эмбеддинги находят фрагменты |
| Документ удалён автором | Пропадает из будущих ответов, кэш сбрасывается |
| Перезапуск во время индексации | Документ становится `failed`, повторная загрузка того же файла возможна |
| БД недоступна | Бот ждёт её при старте, при обрыве зверю: «сервіс тимчасово недоступний» |

## 9. Смена LLM-провайдера

Доступ организации автора к Groq ограничен, поэтому используются бесплатные модели OpenRouter.
Это отклонение от задания: о нём сообщается Broscorp и указано в README. Адаптер
(`openrouter.py`) и политики (`error_policy.py`, `free_filter.py`, `quota.py`) изолированы от
остального кода: возврат к Groq требует нового адаптера и записи в реестре.

## 10. Данные

`documents`: `id`, `sha256` (уникальный), `title`, `filename`, `source_type` (`archive`, `user`),
`source_path`, `uploader_tg_id`, `uploader_name`, `uploader_username`, `uploaded_at` (UTC),
`size_bytes`, `format`, `chunk_count`, `status` (`processing`, `ready`, `failed`).
`chunks`: `document_id` (`ON DELETE CASCADE`), `chunk_index`, `page`, `section`, `content`,
`embedding` (`vector` без размерности). `app_meta`: модель и размерность эмбеддингов.
Расстояние косинусное (`<=>`), векторы нормализованы.

## 11. Критерии приёмки

Сценарии T1–T22 описаны в ТЗ v1.2 (разделы 15 и 20). Дополнительные сценарии T23–T24 фиксируют выполненную ручную проверку и Docker-запуск. Автоматически проверены: логика приёма, дубли, архив (добавление, переименование, удаление, повышение), `/mydocs` (в том числе подделка callback), кэш и его сброс, лимиты, классификация ошибок провайдера, разбор документов.
Качество поиска измеряется `scripts/eval_retrieval.py` по `tests/eval/questions.json`; один успешный ручной E2E-прогон не заменяет такой набор оценки.

|---|---|---|
