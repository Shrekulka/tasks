Файл создаётся скриптом `python -m scripts.gen_config_docs` из `.env.example`. Не редактируйте его
вручную: правьте комментарии и значения в `.env.example`.

## LLM (бесплатные модели OpenRouter)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_API_KEYS` | (пусто) | Ключ создаётся на openrouter.ai в разделе Keys, банковская карта не нужна. Можно несколько ключей через запятую: key1,key2. ВАЖНО: по правилам OpenRouter дополнительные ключи и аккаунты лимиты НЕ увеличивают (ёмкость считается глобально). Несколько ключей нужны только как страховка на случай отзыва одного из них. Не создавайте лишние аккаунты ради обхода лимитов. Ключ обязателен для запуска. Заглушки допустимы только в unit-тестах (tests/conftest.py). |
| `LLM_API_KEY` | (пусто) | Запасной вариант для одного ключа: используется, только если LLM_API_KEYS пуст |
| `LLM_MODELS` | (пусто) | Модели, которые пробуются первыми (через запятую, у бесплатных id заканчивается на :free). Остальные бесплатные бот находит сам по списку https://openrouter.ai/api/v1/models |
| `LLM_MODELS_BLOCKLIST` | (пусто) | Модели, которые использовать нельзя (через запятую) |
| `LLM_PROVIDER` | `openrouter` | Адаптер провайдера. Сейчас поддерживается: openrouter |
| `LLM_BASE_URL` | (пусто) | Пусто = адрес по умолчанию из адаптера. Менять имеет смысл только вместе с адаптером. |
| `LLM_MIN_CONTEXT` | `8000` | Минимальный контекст модели (токены) и время жизни списка моделей (секунды) |
| `LLM_CATALOG_TTL_SECONDS` | `3600` | (см. описание выше) |
| `LLM_RATE_PAUSE_SECONDS` | `60` | Пауза после общего лимита и после блокировки аккаунта (402), секунды |
| `LLM_ACCOUNT_PAUSE_SECONDS` | `900` | (см. описание выше) |
| `LLM_KEY_QUARANTINE_SECONDS` | `3600` | На сколько отключать неверный или исчерпанный ключ, и модель (или пару «модель + ключ»), секунды |
| `LLM_MODEL_QUARANTINE_SECONDS` | `600` | (см. описание выше) |
| `LLM_QUOTA_CACHE_SECONDS` | `30` | Как долго верить закэшированному остатку дневной квоты провайдера, секунды |
| `LLM_DAILY_REQUEST_LIMIT` | `0` | Запасной локальный лимит запросов в сутки (UTC), если провайдер не сообщает остаток. 0 = выключен |
| `LLM_PAIR_FAILURES_BEFORE_MODEL_QUARANTINE` | `2` | Сколько разных ключей должны получить отказ (403) от модели, чтобы отключить её целиком. Так модель, закрытая для вашего региона или аккаунта, не тратит по запросу на каждый ключ |
| `LLM_TEMPERATURE` | `0.1` | Параметры генерации: температура и потолок длины ответа, токены |
| `LLM_MAX_TOKENS` | `600` | (см. описание выше) |
| `LLM_MAX_LIMITED_ATTEMPTS` | `2` | Сколько ответов 429 от поставщика терпим за один вопрос, затем общая пауза для всех (дальше попытки только тратят суточный лимит) |
| `LLM_LIMIT_PAUSE_SECONDS` | `60` | Длина общей паузы после исчерпания таких попыток, секунды (0 = без паузы) |
| `LLM_JSON_MODE` | `auto` | JSON-режим ответа: auto (включается, если модель заявила поддержку response_format) или off |
| `LLM_INVALID_RESPONSE_STRATEGY` | `strict_retry` | Что делать, если ответ модели не прошёл проверку (JSON, язык): strict_retry = один повтор на той же модели с более строгим запросом, затем безопасное сообщение (так сказано в ТЗ); next_model = сразу следующая модель |
| `LLM_UPSTREAM_QUARANTINE_SECONDS` | `60` | На сколько секунд отключать модель после 429 её поставщика (учитывается и Retry-After; 0 = не отключать) |
| `LLM_COUNT_FAILED_REQUESTS` | `true` | Считать ли в локальный счётчик дневной квоты запросы без ответа: таймауты, 429, 5xx (консервативно: true) |
| `LLM_DAILY_RESET_THRESHOLD_SECONDS` | `3600` | Пауза от провайдера не короче этого значения считается исчерпанием дневного лимита, секунды |
| `LLM_TIMEOUT_SECONDS` | `20` | Таймаут одного запроса, секунды |
| `LLM_DEADLINE_SECONDS` | `45` | Общий лимит времени на все попытки (не меньше таймаута одного запроса) |
| `LLM_MAX_MODELS_TRIED` | `3` | Сколько разных моделей максимум пробуем на один вопрос |
| `LLM_MAX_RPM` | `15` | Потолок запросов к LLM в минуту на всех зверей. Реальные лимиты провайдера смотри в его документации: они могут изменяться и различаться для разных ограничений. |

## Поиск по документам

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `EMBEDDING_MODEL` | `intfloat/multilingual-e5-base` | (см. описание выше) |
| `EMBEDDING_DIM` | `768` | Размерность вектора обязана совпадать с моделью (для multilingual-e5-base это 768) |
| `EMBEDDING_QUERY_PREFIX` | `query:` | Префиксы для моделей семейства e5 (без них качество поиска падает без единой ошибки). Для моделей без префиксов оставьте значения пустыми. Пробел после префикса добавляет код. |
| `EMBEDDING_PASSAGE_PREFIX` | `passage:` | (см. описание выше) |
| `EMBEDDING_BATCH_SIZE` | `16` | Сколько текстов считать за один проход модели эмбеддингов |
| `TOP_K` | `5` | Сколько фрагментов достаём из базы на один вопрос |
| `RETRIEVAL_CANDIDATE_FACTOR` | `4` | Во сколько раз больше кандидатов брать из БД, чем TOP_K (нужно, чтобы в ответ попали разные документы) |
| `MAX_CONTEXT_CHARS` | `6000` | Потолок суммарного размера фрагментов в промпте, символы |
| `PROCESSING_NOTICE_AFTER_SECONDS` | `5` | Если индексация документа идёт дольше этого числа секунд, бот пишет «обробляю», а по окончании «готовий» (0 = всегда) |
| `LARGE_DOCUMENT_CHARS` | `10000` | Резерв к порогу по времени: документ с таким числом символов текста и больше считается большим, и «обробляю» уходит сразу (0 = выключено) |
| `ANSWER_LANGUAGE` | `uk` | Язык ответов модели: код профиля из services/language.py (сейчас uk). Проверка языка отсекает, например, русский |
| `PROMPTS_DIR` | `data/prompts` | Каталог текстов промптов (system.txt, strict_reminder.txt; свой промпт языка: <код>/system.txt, см. data/prompts/README.md) |
| `LANGUAGE_PROFILES_DIR` | `data/languages` | Каталог JSON-профилей языков ответа (по файлу на язык, см. data/languages/README.md) |
| `LANGUAGE_MARKER_MIN_CHARS` | `60` | С какой длины ответа (в буквах) обязательны буквы языка ответа (для uk: і ї є ґ) или служебные слова языка |
| `ANSWER_CACHE_TTL_SECONDS` | `3600` | Кэш ответов: время жизни (секунды, 0 = выключен) и число записей. Экономит дневную квоту LLM |
| `ANSWER_CACHE_MAX_ENTRIES` | `500` | (см. описание выше) |
| `RELEVANCE_THRESHOLD` | `0.25` | Максимальное косинусное расстояние, при котором фрагмент считается подходящим. Для multilingual-e5-base на живых вопросах лучшее расстояние у законных вопросов доходило до 0.243, поэтому порог свободный: лишнее отсеивает LLM (found=false). Подбор: scripts.eval_retrieval |
| `RELEVANCE_MARGIN` | `0` | Дополнительный отсев шума: оставлять фрагменты не дальше лучшего + это значение. 0 = выключено. Пробуйте через: python -m scripts.eval_retrieval --margin 0.05 |
| `CHUNK_SIZE` | `1000` | (см. описание выше) |
| `CHUNK_OVERLAP` | `200` | (см. описание выше) |
| `ARCHIVE_HOST_DIR` | `./samples/archive` | Папка со стандартными документами на компьютере (для настоящего архива: ./archive) |
| `ARCHIVE_CONTAINER_DIR` | `/app/archive` | Куда папка монтируется внутри контейнера Docker (только для чтения) |
| `ARCHIVE_DIR` | `./samples/archive` | Путь к документам при локальном запуске без Docker |
| `MAX_FILE_MB` | `20` | Лимит размера файла, МБ (не больше 20: боты не скачивают файлы крупнее) |
| `MAX_PDF_PAGES` | `500` | Защита от тяжёлых файлов: страниц в PDF, записей в ZIP (DOCX), размер DOCX после распаковки, МБ |
| `MAX_ZIP_ENTRIES` | `2000` | (см. описание выше) |
| `MAX_UNPACKED_MB` | `100` | (см. описание выше) |

## Логи
