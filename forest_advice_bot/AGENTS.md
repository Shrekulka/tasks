# Правила проекта для кодинг-агента

Telegram-бот лесных порад: отвечает на вопросы зверей по общей базе документов (RAG) и всегда
называет источник. Требования и решения: `docs/requirements.md`. Переменные окружения: `docs/configuration.md`.

## Ограничения
- Python 3.12, aiogram 3, PostgreSQL + pgvector, SQLAlchemy 2.0 async. Django и FastAPI не используем.
- LLM только бесплатные модели OpenRouter (id с суффиксом `:free`, подтверждённая нулевая цена и текстовый ввод/вывод). Платные модели и покупка кредитов не используются. Исходное задание называло Groq (доступ организации автора ограничен): это отклонение нужно явно сообщить Broscorp перед сдачей; не утверждать, что Broscorp уже согласовал замену без подтверждения.
- Всё запускается одной командой: `docker compose up --build`.
- Секреты только из переменных окружения. Никогда не логировать токены и ключи.
- Документы «Лісового архіву» не публикуем. В репозитории только придуманные примеры
  из `samples/archive/`.
- Все тексты бота на украинском, и только в `lexicon/lexicon_uk.py`.
- Бот отвечает строго по найденным фрагментам документов. Название документа, автора и дату
  в ответ подставляет код из базы, а не модель.
- Конфигурация создаётся явным `load_config()` в `main()`, а не при импорте модуля.
- Зависимости передаются через внедрение зависимостей aiogram, без глобальных объектов.
- Новая зависимость только с обоснованием. `langchain` не нужен.
- Выбирать самое простое решение. У каждой функции должна быть понятная польза.
- Не утверждать ничего о внешнем API (OpenRouter, Telegram), чего не проверили скриптом, документацией
  или тестом.

## Правила для клиента LLM (OpenRouter)
- Список моделей берём динамически (`GET /models` у адаптера, кэш `LLM_CATALOG_TTL_SECONDS`).
  Постоянного списка моделей в коде нет.
- Отбор fail-closed (`external_services/llm/free_filter.py`): модель принимается, только если
  по данным каталога подтверждено всё: id оканчивается на `:free`, `pricing` есть и все цены
  равны 0, текстовый вход и выход, `context_length` число не меньше `LLM_MIN_CONTEXT`.
  Нет данных значит модель отклонена. Платные модели не используем никогда.
- Модели из `LLM_MODELS` проходят тот же фильтр. Пустой список после фильтра: сообщаем
  «сервис временно недоступен», платный fallback запрещён.
- Лимиты бесплатных моделей общие на аккаунт, лишние ключи и аккаунты их не увеличивают.
  Значения лимитов в коде не зашиваем: сверяем с документацией провайдера.
- Ответы провайдера классифицирует `error_policy.classify` по статусу, заголовкам и телу, не
  по одному коду. 401: карантин ключа. 402: если `limit_source` указывает на лимит ключа, то
  карантин ключа, иначе блокировка аккаунта (ретраи запрещены); учитываем `Retry-After`.
  403 без распознанной причины: карантин пары «модель + ключ». 429: наличие заголовков
  `X-RateLimit-*` значит общий лимит платформы (общая пауза), их отсутствие значит лимит
  поставщика (следующая модель). 400 и 404 наказывают модель только при подтверждающем
  маркере в сообщении, иначе следующая попытка без карантина. 5xx и таймаут: следующая модель.
- Дневной остаток бесплатных запросов берём из `free_model_daily_requests` в `GET /key`,
  локальный счётчик запасной.
- Перебор ограничен `LLM_MAX_MODELS_TRIED` и дедлайном `LLM_DEADLINE_SECONDS`.
- Ответ, не прошедший проверку (пустой, не-JSON, не украинский), считается неудачей.

## Структура
- `bot.py`: корень композиции. Единственное место, где создаются объекты (`build_services`).
- `handlers/` тонкие обработчики: разобрать событие, вызвать сервис, ответить. Без SQL и без вызовов LLM.
- `services/` бизнес-логика: `ingestion`, `parsers`, `chunker`, `embeddings`, `retrieval`,
  `answering`, `archive_sync`, `answer_cache`, `background`, `evaluation`.
- `models/` ORM-модели и все запросы к БД (`methods.py`). `database/` подключение и схема.
- `external_services/llm/` адаптер провайдера, клиент моделей, политики (см. правила ниже).
- `errors/` исключения и их перевод в тексты для зверя. `lexicon/` все тексты бота.
- `middlewares/`, `filters/`, `keyboards/`, `utils/`, `config_data/`, `scripts/`, `tests/`.

## Скриншоты и доказательства ручной проверки
- Скриншоты документации хранить в `docs/screenshots/`, а не в корне проекта. Использовать имена `NN-kebab-case.png`; ссылки на них добавлять в `README.md` относительными путями.
- Не подменять ожидаемыми результатами фактические результаты: отмечать сценарий PASS только после проверки в Telegram/БД. В README уже отражён подтверждённый E2E-прогон от 23.10.2026.
- Перед публичной публикацией проверять скриншоты на токены, номера телефонов, карточки контактов и не предназначенные для публикации имена/`@username`. Не публиковать полный вывод `docker compose config`: он подставляет секреты из окружения.
- Тестовый файл ручного RAG-сценария хранить в `docs/examples/`, не в `samples/archive/`: каталог `samples/archive/` синхронизируется в рабочую базу при старте.

## Команды
- `ruff check . && ruff format --check . && pytest`: обязательны после каждого шага.
- Integration-тесты нужен PostgreSQL с pgvector: `TEST_DATABASE_URL=postgresql+asyncpg://… pytest`.
  Без переменной они пропускаются.
- `python -m scripts.eval_retrieval`: качество поиска и подбор порога (нужна настоящая модель).
- `python -m scripts.gen_config_docs`: обновить `docs/configuration.md` после правки `.env.example`.

## Как добавить
- **Переменную окружения:** прочитать в `config_data/config.py` с валидацией, добавить в
  `.env.example` с комментарием, в `CONFIG_ENV_NAMES` (`tests/conftest.py`), выполнить
  `gen_config_docs`. Тест `tests/test_env_sync.py` падает, если что-то забыто.
- **Формат документов:** одна запись `FormatSpec` в `services/parsers.py`. Тексты бота и
  проверки строятся из `supported_extensions()`.
- **LLM-провайдера:** адаптер по интерфейсу `LLMProvider` и запись в `registry.py`.
- **Текст бота:** только в `lexicon/lexicon_uk.py`.

## Порядок работы
- Один шаг, один небольшой коммит, тесты зелёные до перехода дальше.
- Перед коммитом проверить: лишние обращения к внешним API, падения на пустых данных,
  секреты в логах и в истории git.
- В `.gitignore` папка архива записана как `/archive/` (с косой чертой в начале): запись
  `archive/` скрыла бы и `samples/archive/`. Тест `tests/test_deploy_files.py` это проверяет.
